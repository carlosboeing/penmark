## Planned release phases (per design §11)

- **Phase 0 — Foundation**: scaffold (TypeScript, esbuild), CI matrix (3 OS × VS Code 1.105/stable/insiders), 4-layer test harness, VSIX smoke-install across VS Code/Cursor/Antigravity.
- **Phase 1 — Reading MVP (v0.1)**: custom webview preview panel; GitHub-style light/dark/auto themes independent of IDE theme; GFM rendering (markdown-it, host-side parse); syntax highlighting; scroll sync; code-block copy buttons; mermaid lazy render + lightbox modal; DOMPurify + nonce CSP.
- **Phase 2 — Review MVP (v0.5)**: select-to-comment in preview; subtle highlights; comments drawer; resolve/delete; comment storage v1 (documented public spec); author identity; "copy review as prompt" + export review.md (agent handoff).
- **Phase 3 — Polish (v1.0)**: settings (fonts, sizes, line spacing, theme presets); image lightbox; interactive task checkboxes; frontmatter metadata card; basic keyboard navigation; performance pass against budgets. *(CONTRIBUTING / CODE_OF_CONDUCT / issue+PR templates / Discussions landed early on 2026-06-14 when the repo went public.)* Dual-registry launch remains deferred *(repo is public as of 2026-06-14, but marketplace publishing is still a separate deferred decision — ADR 0004 amendments)*.
- **Phase 4 — v2**: comment threads/replies; comment markers in TOC/scrollbar + next/prev navigation; PlantUML (Kroki, configurable server); diagram PNG/SVG export; agent integration (an agent skill, `languageModelTools`, possibly MCP); edit-mode exploration (CustomTextEditor, `priority: "option"`).

## Future considerations

- **Self-hosted/deployable web app** offering the same review experience outside the IDE, connected to a GitHub repo — premise for keeping the render/comment core platform-agnostic and the comment format an open protocol.
- **"Send review to agent" integrations** (Carlos, 2026-06-12): beyond clipboard/file export, detect a running coding agent or terminal session and inject the review prompt directly. Deferred for session-detection complexity across three IDEs; design §4.3.
- **Comment deep links (2026-07-27):** a URI handler so `vscode://<extension-id>/open?file=<path>&comment=<id>` opens a document in Penmark preview and reveals one comment, giving agents and external tools the navigation the comments drawer's "Open" button already provides. The webview half exists (`drawer.ts` scrolls and opens the popover; `scrollToCommentId` in `highlights.ts` handles keyboard nav), but both are pure DOM work that never messages the host — so nothing is callable from outside. Missing: `registerUriHandler` plus an `onUri` activation event, a targetable variant of `penmark.openPreview` (it currently takes no arguments and reads the active editor), and a host-to-webview `revealComment` message. The reveal must queue until the first comments render, since a deep link opens a cold panel. Deferred on the publisher ID: the URL authority is the extension ID, still the local dev value, so link shapes are not stable enough for agents to emit until publishing is decided. Prompted by a cross-harness review test where `path:line` output could not reveal a mis-anchored comment.
- Doc-revision diff review (re-review only what changed since last review round).
- Workspace-level review view (tree of docs with open-comment counts).
- Worker-thread markdown parsing for very large documents.
- Additional diagram formats behind the same fence abstraction (Graphviz/DOT via viz-js WASM, D2).
- Comment format interop (CriticMarkup import/export).
- **Mermaid diagram compaction (cosmetic, deferred 2026-06-14):** tall/large flowcharts could be made more compact by tuning mermaid's `flowchart.padding` (smaller node padding, ~15→8) and `rankSpacing` (gap between nodes, ~50→35) in `initMermaid` — shorter diagrams with the text size unchanged. Measured ~7–14% height reduction before boxes look cramped; affects all flowcharts (a small divergence from mermaid defaults). Purely cosmetic; revisit if tall diagrams become a nuisance. Rejected alongside it: a *scaling* max-height (shrinks text — reintroduces the small-text problem) — prefer the Expand lightbox for full-detail viewing.

## Recently shipped

- 2026-08-27 — **Agent-authored character entities render as punctuation** — review text such as `Layer&#45;1` used to show the entity source in the drawer and popover because Penmark decoded only its paired-hyphen storage sentinel. Penmark now renders any valid decimal character reference where a comment reaches the preview or an export, using markdown-it's validity rule so surrogates, NUL and control characters stay literal instead of becoming ill-formed text a save could write to disk. The pass runs at the display seam rather than in the storage codec, which keeps quote recovery matching raw document bytes and leaves the spec's round-trip guarantee unnarrowed. Format spec §6 and regression coverage updated. Version 0.5.6. See [CHANGELOG.md](CHANGELOG.md).
- 2026-08-10 — **Commenting no longer breaks the formatting it wraps** — commenting a bullet that opened in bold showed the literal `**` in the preview. A line beginning with `<!--` is an HTML block in CommonMark, so an anchor snapped to the start of a bullet, paragraph or blockquote froze that whole line's inline markdown as source — bold, inline code, links and italics alike. The renderer now keeps such lines on the inline path, while marker-only lines (`pmk:b`, `pmk:r`) keep their block behaviour. A second defect surfaced alongside it: a span across list items wrapped `</li><li>` in one `<mark>`, which the browser silently truncates to the first item, so the extent is now split into one `<mark>` per inline run sharing the comment id. Version 0.5.5. See [CHANGELOG.md](CHANGELOG.md).
- 2026-07-31 — **Type-aware frontmatter card lists, status borders, and path links** — frontmatter lists (`authors`, `related`, etc.) render as structured lists, keyword arrays (`scope`, `tags`) render as tag chips, `status` sets a semantic accent border on the card, and file paths render as interactive links that open in the editor. Merged as PR #43 (`7bd4e82`), version 0.5.3. See [CHANGELOG.md](CHANGELOG.md).
- 2026-07-26 — **Comment format survives a format-on-save** — comments could vanish from the preview and the drawer after an ordinary save: the writer emitted an empty quote line as `"> "`, every formatter strips that trailing space, and the reader required the `"> "` prefix. The writer now emits a bare `>` and separates the review block from the body with a blank line; the reader accepts both quote forms and tolerates entries a reflowing tool has indented; unreadable review data raises the attention count instead of failing silently. New tests push each fixture's serialized output through real Prettier and trailing-whitespace trimming before re-parsing — the closed-loop round-trip suites could not have caught this. Format spec §5.2.2 and writer invariant 2 updated. See [CHANGELOG.md](CHANGELOG.md).
- 2026-07-26 — **Panel, search and typography bug bash** — fixed ten defects across the adaptive review surface, search toggle, drawer header, settings link, narrow-viewport bottom sheet, body typography inheritance, frontmatter card alignment, and block-sequence parsing, and reworked the five typography presets into four distinct ones with per-preset heading scales (`print` retired). Merged as PR #38 (`worktree-panel-typography-bug-bash`), version 0.5.1. See [CHANGELOG.md](CHANGELOG.md).
